# Деплой через Coolify

Coolify — self-hosted платформа: git-push деплой, автоматический HTTPS, управление переменными, логи, откат. Ниже порядок действий с нуля.

## 1. Сервер и домен

- VPS с Ubuntu 24.04, минимум 2 vCPU и 4 GB памяти.
- **Сервер только российский.** Часть 5 статьи 18 закона 152-ФЗ требует, чтобы база с персональными данными россиян физически находилась в России. Selectel, Timeweb Cloud, RuVDS подходят; зарубежный хостинг сделает уведомление в Роскомнадзор недостоверным. Развёрнуто на Timeweb Cloud, Москва.
- Домен с A-записью на IP сервера. До покупки домена Coolify выдаёт временный адрес вида `*.sslip.io`.
- Вход на сервер по SSH-ключу, пароль отключить.

**Заранее, до развёртывания:** Timeweb по умолчанию закрывает исходящие почтовые порты 25, 465, 587 и 2525 — это защита от рассылок. Без них письма о регистрации и восстановлении пароля отправить нельзя. Откройте чат поддержки и попросите разблокировать 465 и 587 для вашего сервера: проверку делает специалист, ответ занимает несколько часов. Список закрытых портов виден в карточке сервера.

## 2. Установка Coolify

На сервере под root:

```bash
curl -fsSL https://cdn.coollabs.io/coolify/install.sh | bash
```

После установки открыть `http://<ip>:8000`, создать первого администратора, в настройках указать домен панели и включить HTTPS.

## 3. GitHub

В Coolify: Sources → Add → GitHub App. Coolify сам создаст GitHub App и попросит дать ему доступ к репозиторию `uyut`. После этого деплой запускается автоматически на каждый push в `main`.

## 4. Проект и ресурсы

Создать проект `uyut`, окружение `production`, добавить ресурсы:

**PostgreSQL.** Тип Database → PostgreSQL. В настройках образа указать `pgvector/pgvector:pg17`, иначе расширения vector не будет. Внутренний URL подключения скопировать в переменную `DATABASE_URL` приложения.

**Redis с REST-прокси.** Тип Docker Compose, вставить содержимое `infra/coolify/redis-srh.compose.yml`. Задать переменные `REDIS_PASSWORD` и `SRH_TOKEN` (длинные случайные строки). Включить «Connect to predefined network», чтобы приложение видело сервис по имени `redis-http`.

**Приложение.** Тип Application → Private repository (GitHub App), репозиторий `uyut`, ветка `main`.
- Build pack: Dockerfile.
- Base directory: `/`.
- Dockerfile location: `/apps/web/Dockerfile`.
- Port: `3000`.
- Health check: путь `/api/health`.
- Домен: `https://<ваш домен>`.

Миграции применяются автоматически при старте контейнера, отдельного шага не нужно.

## 5. Переменные окружения приложения

Разделены по смыслу. Пустое значение у необязательной переменной означает «эта часть выключена», приложение поднимется и без неё.

### Обязательные

| Переменная | Значение |
|---|---|
| `APP_URL` | `https://<ваш домен>` |
| `DATABASE_URL` | внутренний URL PostgreSQL из Coolify |
| `UPSTASH_REDIS_REST_URL` | `http://redis-http:80` |
| `UPSTASH_REDIS_REST_TOKEN` | значение `SRH_TOKEN` |
| `S3_ENDPOINT` | `https://s3.twcstorage.ru` — адрес хранилища из панели |
| `S3_REGION` | `ru-1` |
| `S3_BUCKET` | `uyut-prod` — приватный бакет для файлов сервиса |
| `S3_ACCESS_KEY`, `S3_SECRET_KEY` | ключи доступа из карточки бакета |
| `BETTER_AUTH_SECRET` | случайная строка от 32 символов, `openssl rand -base64 32` |
| `SMTP_URL` | адрес SMTP-сервера, например `smtps://user:pass@smtp.yandex.ru:465` |
| `EMAIL_FROM` | отправитель писем, например `Uyut <hello@ваш-домен>` |

### Работа за обратным прокси

| Переменная | Значение |
|---|---|
| `TRUSTED_PROXY_HOPS` | `1` |

Coolify ставит перед приложением обратный прокси, и адрес клиента приходит в заголовке `X-Forwarded-For`. Значение `1` означает «перед нами один свой прокси»: адрес берётся последней записью, которую этот прокси и дописал, а подставленное клиентом отбрасывается. **Без этой переменной ограничения по частоте запросов и записи аудита будут считаться по подделанному адресу.** Если однажды поставите перед Coolify ещё один прокси или CDN, увеличьте число на единицу.

### Внешние модели

| Переменная | Значение |
|---|---|
| `FAL_KEY` | ключ fal.ai; без него генерация вариантов недоступна |
| `CONCEPT_MODEL` | `nano-banana-2` (по умолчанию) или `kontext-pro` |
| `VOYAGE_API_KEY` | ключ Voyage AI для подбора товаров по картинке |
| `TRIGGER_SECRET_KEY` | ключ окружения Trigger.dev; без него не запускаются фоновые задачи |
| `ANTHROPIC_API_KEY` | не используется, оставить пустым: модели вызываются через fal |

### Оплата

| Переменная | Значение |
|---|---|
| `YUKASSA_SHOP_ID` | shopId боевого магазина |
| `YUKASSA_SECRET_KEY` | секретный ключ магазина; боевой начинается не с `test_` |
| `YUKASSA_API_URL` | пусто (используется `https://api.yookassa.ru/v3`) |
| `PROJECT_PRICE_KOPECKS` | `150000` — разовая покупка проекта, 1 500 ₽ |
| `PRO_PRICE_KOPECKS` | `99900` — месяц Pro, 999 ₽ |

Пока ключей нет, платежи идут через фейковый провайдер: оплата проходит сразу и без списания. Это нормально для первого запуска, но продавать так нельзя.

### Смета и документы

| Переменная | Значение |
|---|---|
| `WORKS_ROUGH_RUB_PER_M2` | `15000` — ориентир черновых работ |
| `WORKS_FINISH_RUB_PER_M2` | `5000` — ориентир чистовых работ |
| `PDF_URL_TTL_HOURS` | `168` — срок ссылки на PDF из письма, максимум 168 |

### Служебные

| Переменная | Значение |
|---|---|
| `CRON_SECRET` | случайная строка, `openssl rand -hex 32`. Ей защищён ежедневный проход по подпискам; без неё маршрут отвечает 404 и продления не работают |
| `SENTRY_DSN` | DSN production-проекта Sentry |
| `NEXT_PUBLIC_SENTRY_DSN` | тот же DSN, отметить «Available at build time» |
| `NEXT_PUBLIC_POSTHOG_KEY` | ключ проекта PostHog, отметить «Available at build time» |
| `NEXT_PUBLIC_POSTHOG_HOST` | `https://eu.i.posthog.com`, отметить «Available at build time» |
| `MAILPIT_URL` | оставить пустым, нужен только локально |

Переменные с приставкой `NEXT_PUBLIC_` вшиваются в клиентский код при сборке. Если задать их после сборки, они не подхватятся: нужно пересобрать приложение.

## 6. Фоновые задачи

Задачи работают в Trigger.dev Cloud, на сервере ничего разворачивать не нужно. Деплой делает GitHub Actions: в секреты репозитория добавить `TRIGGER_ACCESS_TOKEN` (личный токен из Trigger.dev) и `TRIGGER_PROJECT_REF`, после чего workflow запускает `trigger.dev deploy` на каждый push в `main`.

**Воркер живёт отдельно от сервера и своих переменных из Coolify не видит.** Их задают в кабинете Trigger.dev: Project → Environment Variables → production.

| Переменная | Зачем воркеру |
|---|---|
| `DATABASE_URL` | читает и пишет проекты, концепты, экспорты |
| `S3_ENDPOINT`, `S3_REGION`, `S3_BUCKET`, `S3_ACCESS_KEY`, `S3_SECRET_KEY` | кладёт рендеры и готовые PDF |
| `FAL_KEY` | генерация вариантов и разбор предметов на рендере |
| `VOYAGE_API_KEY` | векторы для подбора товаров |
| `APP_URL` | ссылки в письмах |
| `SMTP_URL`, `EMAIL_FROM` | письма о готовности проекта и о подписке |
| `PDF_URL_TTL_HOURS` | срок ссылки на PDF |
| `WORKS_ROUGH_RUB_PER_M2`, `WORKS_FINISH_RUB_PER_M2` | смета внутри документа |
| `CRON_SECRET` | тем же ключом задача стучится в ежедневный проход по подпискам |
| `ADMITAD_FEED_OZON_URL` и подобные | товарные фиды магазинов; имя источника берётся из имени переменной |

Расписание `subscriptions-daily` запускается само раз в сутки в 9:00 UTC и дёргает `POST /api/cron/subscriptions` на `APP_URL`, передавая секрет заголовком `x-cron-secret`. Проверить вручную:

```bash
curl -s -X POST https://<ваш домен>/api/cron/subscriptions -H "x-cron-secret: <CRON_SECRET>"
```

Вторым расписанием работает `index-catalog`: раз в сутки в 3:00 UTC оно перечитывает товарные фиды и пересчитывает векторы. Пока переменных `ADMITAD_FEED_*_URL` нет, задача только обновляет векторы у того, что уже лежит в базе.

Ответ вида `{"ok":true,...}` означает, что проход выполнен. Ответ 404 — не задан `CRON_SECRET`, 403 — секрет не совпал с тем, что прописан у воркера.

## 7. Боевой контур ЮKassa

1. В кабинете ЮKassa подписать оферту и получить боевые ключи магазина, вписать их в переменные приложения.
2. Раздел «HTTP-уведомления»: адрес `https://<ваш домен>/api/webhooks/yukassa`, события `payment.succeeded` и `payment.canceled`.
3. Включить автоплатежи для магазина — без них не будет автопродления Pro, код продления уже написан.
4. Провести живую покупку на 1 ₽ и вернуть её через кабинет.

Уведомления принимаются только с адресов ЮKassa; телу уведомления приложение не доверяет и всегда перечитывает платёж из API. Если адрес уведомлений указан неверно, оплата всё равно засчитается при возврате пользователя на сайт, но с задержкой.

## 8. Аналитика

**PostHog Cloud** уже подключён переменными выше, разворачивать нечего.

**Umami** — свой счётчик посещений. В Coolify: Add Resource → Services → Umami, база создаётся автоматически. Домен `https://umami.<ваш домен>`. После установки создать сайт, скопировать `Website ID` и добавить скрипт в приложение отдельной задачей: пока код счётчика в приложении не подключён.

## 9. Мониторинг

Уровня два, и они не заменяют друг друга.

### Внешний сторож — обязательно

**Мониторинг, живущий на том же сервере, не сообщит о смерти этого сервера.** Если машина уйдёт в перезагрузку или кончится диск, вместе с ней замолчит и Uptime Kuma — то есть ровно в тот момент, когда оповещение и нужно. Поэтому первым делом заводится проверка снаружи.

Подойдёт любой бесплатный сервис такого рода, например UptimeRobot: регистрация, Add New Monitor → HTTP(s), адрес `https://<ваш домен>/api/health`, интервал 5 минут, в оповещениях выбрать Telegram и указать бота.

У внешнего сторожа есть ещё одно достоинство: он шлёт сообщение со своей стороны, поэтому доступность Telegram с российского сервера для него не имеет значения.

### Uptime Kuma на сервере — для внутреннего

В Coolify: Add Resource → Services → Uptime Kuma, домен `https://status.<ваш домен>`. Он видит то, чего не видно снаружи: жива ли база, отвечает ли Redis, не переполнился ли диск.

Проверки:
- `https://<ваш домен>/api/health` каждую минуту, ответ содержит `"status":"ok"` — покажет, что база отвечает.
- `http://redis-http:80` по внутренней сети, код 200 или 401.
- Свободное место на диске — Uptime Kuma умеет через push-проверку из cron.

Оповещения в Телеграм: Settings → Notifications → Add → Telegram, вставить `TELEGRAM_BOT_TOKEN` и `TELEGRAM_CHAT_ID` (заведены заранее, лежат в локальном `.env`). Нажать Test — сообщение должно прийти в чат.

### Если Telegram с сервера не отвечает

Telegram в России не заблокирован, и боты обычно работают. Проверить с сервера:

```bash
curl -s "https://api.telegram.org/bot<TELEGRAM_BOT_TOKEN>/getMe"
```

Ответ с `"ok":true` означает, что всё в порядке. Если запрос не проходит, для Uptime Kuma переключиться на оповещения по почте: Settings → Notifications → Add → SMTP, те же данные, что в `SMTP_URL` приложения. Внешнего сторожа это не касается — он шлёт сообщения не с нашего сервера.

## 10. Бэкапы

В настройках базы PostgreSQL включить Scheduled Backups с загрузкой в S3 (отдельный бакет `uyut-backups`, тот же адрес и ключи), расписание ежедневно, хранение 30 копий. Скрипт `infra/scripts/backup.sh` делает то же самое вручную или из cron с ретеншеном «30 ежедневных плюс ежемесячные за год». Раз в квартал проверять восстановление из копии на чистой базе.

## 11. Проверка после развёртывания

```bash
curl -s https://<ваш домен>/api/health
```

Ответ `{"status":"ok","database":"ok"}` означает, что контейнер поднялся, миграции применились и база доступна.

**Проверять доступность нужно с чужой сети**, например с телефона по мобильному интернету. Запрос к собственному публичному адресу, сделанный с самого сервера, не покидает машину: адрес висит на его сетевой карте, и пакет закольцовывается внутри. Такой ответ выглядит как успех, но ничего не доказывает.

Если снаружи не отвечает ничего, а на сервере `ufw` выключен, `iptables -L INPUT` пуст и службы слушают на `0.0.0.0` — дело в сети провайдера, а не в машине. Косвенный признак: в `journalctl -u ssh` почти нет входящих соединений, хотя попыток было много. Это вопрос в поддержку хостинга.

Дальше пройти руками:

- [ ] Главная открывается, фотографии на месте, ссылки на юридические документы в подвале работают.
- [ ] Регистрация: письмо о подтверждении приходит на настоящий ящик.
- [ ] Заголовки безопасности на месте: `curl -sI https://<ваш домен>/ | grep -i content-security-policy` — в ответе должен быть `nonce-`.
- [ ] Адрес клиента разбирается верно: в `audit_log` после входа записан ваш настоящий IP, а не адрес прокси.
- [ ] Онбординг и генерация вариантов комнаты доходят до готовых картинок.
- [ ] Сборка PDF: скачать документ и **открыть обычным просмотрщиком**. Отдельно посмотреть обложку: при просмотре через pdf.js полупрозрачный градиент на ней уходит в розовый оттенок, и пока неясно, дефект это документа или просмотрщика. Если в нормальном просмотрщике обложка тёмная — вопрос закрыт.
- [ ] Оплата на 1 ₽ проходит, уведомление доходит, покупка отмечена оплаченной.
- [ ] События появляются в PostHog.
- [ ] Внешний сторож видит сайт и присылает тестовое сообщение в Телеграм.
- [ ] Uptime Kuma присылает тестовое сообщение в Телеграм. Если нет — проверить доступность `api.telegram.org` с сервера и переключиться на почту.
- [ ] Проверить сторожа боем: остановить приложение в Coolify и дождаться сообщения, потом запустить обратно.
