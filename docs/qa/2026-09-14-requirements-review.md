# Проверка пожеланий после рендера

## Изменения

- Проверяющий получает notes, revision и household из существующего брифа.
- brief_conflict обозначает видимое противоречие; requirement_unconfirmed — пожелание,
  которое кадр не подтверждает. Не запускаем автоматический повтор рендера.
- Размеры передаются без округления до десятых метра. Освещение не требует новых окон.
- Карточка сохраняет оговорки о размерах и неполной проверке; после перекраски старый отчёт скрыт.

## Проверки

388 модульных тестов, включая парсер новых кодов, передачу/ограничение заметок,
невалидные ответы, таймаут без повторного запроса, текст и экранирование карточки.
Проверка типов во всех пакетах и lint выполняются отдельно перед выпуском.

Повторная оценка шести локальных синтетических изображений без новых рендеров:

| Пример | Результат |
| --- | --- |
| narrow-kitchen | unavailable, результат не объявлен проверенным |
| small-family-kitchen | requirement_unconfirmed: три места запрошены, два видны |
| narrow-living | checked, замечаний нет |
| two-window-living | checked, замечаний нет |
| compact-bedroom | checked, замечаний нет |
| windowless-bedroom | checked, замечаний нет |

Два дополнительных запроса на том же изображении two-window-living:
- условие «никаких кресел» → brief_conflict, кресло справа;
- архитектура «нет окон» → opening_conflict, видны два окна.

Всего восемь обращений к проверяющему, ноль новых рендеров.
Не считать контрольные запросы самостоятельными генерациями или оценкой общей точности.
Локальные изображения и сырые ответы исключены из Git.

## QA Release Gate

BLOCKERS для точного проекта по размерам остаются: нет геометрической валидации,
сравнения с исходным планом/фото и гарантированного сохранения архитектуры между вариантами.

IMPORTANT: малая нерепрезентативная выборка; один unavailable; возможны ложные
предупреждения и пропуски. Требуется дальнейшая размеченная выборка.

POLISH: отсутствие предупреждений не означает исполнения всех пожеланий; это явно сказано в UI.

Рекомендация: выпускать как рекомендательное улучшение концептов, не как точную планировку.
Схема JSONB аддитивная, SQL-миграция не нужна; старые отчёты остаются совместимыми.
Старые пользовательские концепты не перезаписывались и не перепроверялись на сайте.
