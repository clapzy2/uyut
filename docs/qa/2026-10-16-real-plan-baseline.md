Эти числа не являются приёмкой 2D/3D. В частности, восемь связей CHI относятся к кандидатам областей, а не подтверждённому свободному полу. На текущей рабочей версии каждый из пяти круглых маркеров Мухановой сохраняет обе исходные ссылки на полуокружности. Даже после этого подтверждение пола лоджии отсутствует.

Дополнительная проверка связей и исходной топологии:

Повторная проверка `nativeRoomNumberScheduleLinks` связала все пять строк Мухановой
с единственными исходными круглыми маркерами (номера 1–5, без лишних маркеров).
Это связь двух документальных наблюдений. Контур физического пола не получен.
Граф исходных штрихов даёт 25 замкнутых граней только в таблицах, легенде и штампе;
в области квартиры замкнутых граней нет. Каждый из 1183 открытых штрихов задан
отдельным двухточечным путём. Ещё 149 замкнутых двухточечных путей вырождены.
Объединения заливок также не имеют отверстий; новый сборщик прямоугольников
здесь продублировал бы существующий граф и выделил таблицы вместо проёмов.

На сайте исходник заменён с разрешения владельца в QA 04.10; страница 4 прочитана,
пять помещений, включая лоджию 4,17 м², показаны для сверки. Геометрия автоматически
не подтверждена; мерки оставлены для уточнения. Найдены отдельные вводящие
в заблуждение предупреждения о сумме площади и произведении пустых сторон.

Запуск из `apps/web`:

```powershell
bun run scripts/qa-real-plan-baseline.ts ../../output/pdf/source-search-20261016/muhanova-original.pdf 4
bun run scripts/qa-real-plan-baseline.ts ../../tmp/pdfs/chigintseva-sample.pdf 3
bun run scripts/qa-real-plan-baseline.ts ../../tmp/received-report-12345/retest-2026-10-09/original-plan.webp
bun run scripts/qa-independent-metric-room.ts ../../tmp/pdfs/chigintseva-sample.pdf ../../docs/qa/fixtures/chigintseva-existing-balcony-08.json
```

Последний запуск сверяет ручную контрольную разметку независимого балкона с исходными размерными цепями: 1390 × 4070 мм, шесть вершин, расчётная площадь 5,51 м² против подписи 5,5 м². Результат `confirmationReady=false`: шесть граней стен не сопоставлены, проёмов нет, внешний контур квартиры и остальные семь комнат отсутствуют. Выход скрипта с кодом 0 означает соответствие ожиданиям контрольной разметки, а не готовность квартиры к подтверждению.

Для проверки локального экспорта тот же скрипт принимает дополнительные пути `overlay.png layout.pdf geometry.json`; это экспорт вручную проверяемой разметки, не автоматическое восстановление пола. Структурированная Swiss Dwellings фикстура и синтетическая квартира с диагональным балконом проверяют потребителей 2D/3D/PDF отдельно, но не заменяют приёмку чтения исходного изображения.

Открытые критерии: доказать физические границы и пороги по исходным штрихам; привязать размеры и высоты к объектам, сохранив общий ноль и стадию обмера; подтвердить и повторно прочитать геометрию в аккаунте; сравнить её в 2D, 3D и PDF. Для нечитаемого растра нужен работающий ручной путь подтверждения с явными неопределённостями. На данном прогоне эти критерии ещё не закрыты.
