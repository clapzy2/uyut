# Повтор после смены сборки, 14 ноября

На живом сайте после PR #296 старая вкладка упала с ChunkLoadError.
Кнопка reset повторяла отрисовку в том же JavaScript runtime и не помогала.
Обычная полная перезагрузка возвращала сохранённую смету и PDF.

## Исправление

Оба экрана отказа при ошибке загрузки сборки по кнопке загружают страницу
целиком, сохраняя URL. Обычные ошибки продолжают использовать reset.
Распознаётся также сообщение Turbopack «Failed to load chunk» без специального
имени Error. Текст не обещает сохранение несохранённых полей и не утверждает,
что сервер недоступен при ошибке загрузки клиентского файла.

Автоматическое восстановление экрана страницы не расширялось: действует прежняя
защита на 30 секунд. Ручной повтор работает и при сработавшей защите, и когда
sessionStorage запрещён. Глобальный экран не делает автоматических reload.

## Локальная проверка

- 10 профильных unit-тестов: распознавание, обе кнопки, обычная ошибка,
  запрещённое хранилище, автоматический повтор и ручной после него.
- Production build и типизация прошли; Biome по исходникам прошёл.
- Полный локальный unit-прогон: 9441 passed. Два E2E прошли вместе:
  восстановление старого JS и сохранение результатов генерации/PDF при повторе.
- Playwright: переход login -> register с блокировкой новых JS chunks.
  Получен настоящий ChunkLoadError и экран повтора. После снятия блокировки
  кнопка восстановила форму регистрации. URL не изменился, ровно один reload,
  POST-запросов нет. Реальные генерация, очередь и экспорт не запускались.

Это проверка недоступного файла сборки, не двух одновременно работающих серверных
версий. Она не доказывает восстановление несохранённых полей после reload.
Уже открытая вкладка со старым кодом кнопки получит исправление только после
обычного обновления страницы; новую функцию в старый runtime выпуск не добавляет.
Расходы на модели $0. Сводные проценты готовности не повышаем.
