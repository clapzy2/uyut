# Сохранение готового результата при восстановлении, 14 ноября

## Найдено и исправлено

1. Повтор PDF заставал активную запись, но при проверке она уже становилась
   ready. Сервер создавал следующую сборку вместо показа готовой. Теперь новая
   попытка допускается в этом пути только после подтверждённого failed;
   остальные состояния отправляют UI на проверку результата.
2. Воркер сохранял PDF, затем отказ уведомления done или логгера попадал в общий
   catch и менял ready на failed. Уведомление отделено от результата; общий
   обработчик отказа также не обновляет готовые строки.
3. Повторное исполнение уже готового exportId снова выполняло сборку. Теперь
   ready с pdfKey возвращает сохранённый результат без модели, печати и загрузки.
   ready без ключа безопасно отклоняется. Условный UPDATE не позволяет позднему
   обработчику перевести ready обратно в running; при отказе обновления он
   перечитывает результат и не начинает подготовку.
4. При недоступной очереди чтение возвращало старый pending/running, даже если
   воркер успел сохранить файл. Повторное чтение БД теперь выполняется также
   при отказе очереди, и готовый файл доступен сразу.

## Проверка

Регрессия лишнего запуска и три регрессии воркера падали до исправления.
После исправления 49 профильных unit-тестов прошли. В настоящей локальной БД
прошли 8 тестов экспорта, включая конкурентные брони и сохранение файла во
время отказа очереди. UI-тест подтверждает переход от неопределённого ответа
к ссылке готового PDF без дополнительного запуска.

Полный локальный unit-прогон: 9447 passed. Production build, типизация и Biome
прошли. Два E2E прошли вместе: сохранение результатов генерации/PDF и безопасная
проверка статуса, восстановление старой вкладки без повторной отправки операций.
После финального ревью добавлен контроль гонки SELECT/UPDATE, 50 профильных
тестов прошли. Это mock-контроль SQL-условия, не конкурентный запуск двух воркеров.

Аудит генерации не нашёл новой воспроизведённой ошибки повторного платного
запуска. Её CAS-брони и привязка batchId не менялись. Статус очереди по возрасту
не завершаем, неопределённые ответы не считаем разрешением нового запуска.

Остаются ограничения: старые заявки без runId и метки требуют операционной
сверки; этот пакет не восстанавливает файл, если загрузка в S3 завершилась,
но запись его ключа в БД достоверно не состоялась. Параллельный ручной запуск
одного exportId непосредственно из панели очереди отдельно не проверялся.
Платные запросы не выполнялись, расход $0. Проценты готовности не повышаем.
