# Изолированная проверка резервной копии — 04.10.2026

Статус: реальное восстановление конкретной копии успешно проверено 04.10.2026
в 19:04 по Москве. Отчёт: `tmp/restore-20261004/report-2.json` (локальный артефакт,
не содержит строк пользователей). Продолжительность — 8,73 секунды.

Первый запуск остановился до восстановления: `docker cp` не поддержал
read-only rootfs, хотя целевой `/tmp` — tmpfs. Передача исправлена на бинарный
stdin через `docker exec -i`, без снятия изоляции. Первый запуск также сохранил
исходный SHA-256 и удалил свой временный контейнер.

Проверка самого скрипта: PowerShell разбирает файл без ошибок. Защита изоляции
приняла одну корректную фикстуру и отклонила восемь нарушений: чужие ID/имя/метку,
сеть bridge, постоянный том, записываемую корневую файловую систему,
опубликованный порт и отсутствующий лимит tmpfs. Docker-ресурсы при этой проверке
не создавались. Учтено, что Docker показывает tmpfs в `HostConfig.Tmpfs`, а массив
`Mounts` при этом может оставаться пустым.

## Что проверяем

Custom-архив PostgreSQL восстанавливается в отдельную локальную базу
`domitsa_restore_check`. Образ `pgvector/pgvector:pg17` должен уже быть в Docker:
скрипт ничего не скачивает и не подключается к рабочей базе.

Команда из корня проекта, в PowerShell 7:

```powershell
./infra/scripts/restore-check.ps1 `
  -ArchivePath 'C:\полный\путь\before-20261004-1420.dump' `
  -OutputReportPath 'C:\полный\путь\restore-check-report.json'
```

Файл отчёта должен быть новым. Поддерживается только архив с заголовком `PGDMP`;
gzip-копия из ежедневного `backup.sh` — другой формат, этот сценарий её не принимает.

## Критерии приёмки

- Создан новый контейнер `domitsa-restore-check-<случайный ID>` с отдельной меткой.
- Нет сети, опубликованных портов, host-mount или постоянных Docker-томов.
  Данные PostgreSQL находятся в tmpfs с лимитом 1 ГиБ; память контейнера — 1536 МиБ.
- `pg_restore --exit-on-error --no-owner --no-privileges` завершился успешно.
- Восстановлены обязательные таблицы, расширение vector и журнал Drizzle.
  Контрольные суммы и даты всех миграций совпали с журналом текущего репозитория.
- Нет невалидированных ограничений, неготовых/невалидных индексов и сиротских
  внешних ключей. Готовые концепты имеют ключ рендера, готовые экспорты — ключ PDF,
  количество товаров положительное.
- JSON содержит только агрегаты, названия таблиц/схем, версии миграций и сведения
  об изоляции. Строки пользователей, пароли, ключи объектов и тексты SQL-ошибок
  восстановления в отчёт и терминал не выводятся.
- SHA-256 исходной копии после проверки не изменился.
- В `finally` удалён только собственный контейнер, после повторной сверки точного
  ID, имени, метки и изоляции. При несовпадении удаление запрещается; это отражается
  как ошибка. Исходный архив и отчёт остаются.

## Граница доказательства

Успешный запуск доказывает восстановимость конкретной копии базы, её структуру
и перечисленные агрегатные связи. Он не восстанавливает S3-файлы, настройки
Coolify/Trigger, платёжные секреты и не доказывает полноценный откат приложения.
Существование ключа PDF/рендера в базе не доказывает наличие самого файла в S3.

Подпункт «восстановление конкретной копии базы» закрыт этим запуском основной
сессии. Полный эксплуатационный пакет остаётся открытым: отдельно нужны
проверка файлового хранилища, документированный откат версии приложения и
доступы/секреты для восстановления сервиса, а не только его базы.
