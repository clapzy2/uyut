# Локальный экспорт: база → PDF → хранилище → браузер

Дата: 2 октября 2026. Проверка только на локальной квартире из
`2026-10-02-open-apartment-browser.md`. Источник её геометрии — открытые
структурированные данные Swiss Dwellings, а не распознанный загруженный PDF.
Платных AI-вызовов не было.

## Что доказано

- Сохранённый проект прошёл `loadSnapshot` и `buildPdfData`, затем тот же
  HTML-шаблон и печать Chromium, которые использует задача экспорта.
- PDF из восьми страниц (1 406 320 байт) записан в локальное S3-хранилище и
  прочитан обратно. SHA-256 созданного файла, хранилища и скачанного с
  итоговой страницы файла совпал:
  `a35b10f81475c906b70bb39e0da85637c7e227e39d619bb271a3caba4ef776a2`.
- Все восемь страниц визуально просмотрены: обложка, обзор, схемы спальни,
  гостиной и кухни, список покупок, смета и заключение читаются без обрезки.
  Предупреждения о предварительности результата присутствуют.
- Независимый регрессионный прогон пяти предоставленных PDF завершился без
  изменений прежних результатов. Это контроль стабильности, не доказательство
  автоматического восстановления полного физического контура.

Для повтора — `jobs/scripts/qa-local-export.ts`: передать ID **локального**
проекта с названием `Локальный тест 2D — …` и локальное окружение `.env.e2e`.
Скрипт откажется работать с удалённой базой, хранилищем или адресом сайта, а
также с настроенным ключом AI или очереди. Он создаёт отдельную запись
экспорта и файл в `output/pdf/`; повторный запуск создаст ещё одну запись.

## Что не доказано

- Нажатие «Собрать PDF» → постановка в Trigger.dev → выполнение задачи.
  Вход CLI в аккаунт Trigger.dev сработал, но локальный обработчик не
  зарегистрировался: сборка завершилась ошибкой соединения. Подмена этого
  звена локальным скриптом проверила остальную цепочку, но не очередь.
- Работа опубликованной версии сайта. Публичная главная страница открылась,
  однако браузер сообщил React hydration `#418`; причина отдельно не
  установлена. Авторизованный production-путь в этой проверке не проходили.
- Получение проверенной геометрии из произвольного плана квартиры.

## Повторная проверка содержания

После исправлений повторно создан и просмотрен восьмистраничный документ.
Замечания к первоначальной версии устранены:

- Подсказки по проёмам используют понятные номера из редактора («Окно 4»,
  «Дверь 2»), а не внутренние ID. Названия также согласованы с настройками
  кухни и резервами открывания.
- Два явно названных балкона выведены из общей ставки ремонта. В PDF и на
  итоговой странице они помечены как отдельный расчёт, а не как нулевая
  стоимость работ. Новая сумма проекта — 1 304 600 ₽ вместо 1 491 200 ₽.
  Это защищает названия, начинающиеся с «Балкон» или «Лоджия», но не заменяет
  полноценный тип помещения: произвольное имя пока требует проверки человеком.
- В заключении без рендеров больше нет обещания показать их в проекте.

Итоговая страница в локальном браузере показала ту же сумму, два исключённых
балкона и новые подписи проёмов. Целевые тесты и проверка типов web/jobs прошли.
Отчёт Trigger.dev за последние 24 часа показывает нормальную работу production
задач, но не подтверждает именно этот новый экспорт после публикации: локальный
обработчик по-прежнему не подключается.

Ни один из этих результатов не закрывает приёмку точного 2D: исходные
неоднозначные PDF по-прежнему требуют независимого обмера или ручного
подтверждения существующих границ.

## Дополнение 4 октября: сохранность текущего плана в PDF

Воспроизведён отказ: кухня с подтверждённым контуром и заданными модулями,
но без покупок и концептов давала пустой список PDF-комнат. Причина — ранний
возврат `null` при отсутствии покупок. Теперь тот же `layoutWithMeasurements`
выполняется и с пустым списком; без исходных мерок он по-прежнему не выдумывает
контур. Шаблон сохраняет подтверждённый пол и печатает `keepClearZones`,
которые раньше участвовали в расчёте, но были невидимы в PDF.

В подписях сохранены оси размеров и дробные сантиметры. Высоты выбранной
мебели берутся из placementInputs, кухонных модулей и потолка — из сохранённых
мерок. Очистка высоты и удаление модуля отражаются при следующей сборке.
Кухонные мерки печатаются только для модулей, связанных расчётом с этой
комнатой; черновой контур не получает модули чужой комнаты. Это комнатный
2D-экспорт, не новый PDF-рендер 3D и не полный лист вертикальных стен.

`loadSnapshot` теперь читает проект, комнаты, покупки и концепты в одной
read-only repeatable-read транзакции. Файл — снимок на момент чтения фоновой
задачей, не живая ссылка и не обязательно состояние на момент клика.
После сборки проект может меняться; у скачивания добавлено явное пояснение
о повторной сборке. `contentHash` остаётся ключом кэша ТЗ, а не доказательством
актуальности всей геометрии PDF. Автоматического признака устаревания пока нет.

Проверки:

- 2118 веб-тестов в 167 файлах; четыре новые регрессии (кухня и последующие
  правки, дробные осевые габариты/высота, пустой пол/препятствия/выход зоны
  за рамку, контракт транзакции). Целевой PDF-набор: 41 тест.
- Типы web/jobs/pdf, сборка сайта, scoped Biome восьми файлов, diff check.
- `cd jobs; bun run scripts/qa-pdf.ts --geometry-flow`: пятистраничный
  `output/pdf/qa-geometry-flow.pdf`, без БД, AI, писем, S3 и сетевых изображений.
  Все пять страниц отрендерены через Poppler и просмотрены; на кухонном листе
  видны модуль и две зоны, подписи и неизвестная высота читаемы, обрезаний нет.
  После последней правки повторно просмотрен лист кухни.
- Poppler выдал `Bad bounding box in Type 3 glyph` при первом растровом
  прогоне; визуального дефекта на просмотренных страницах не обнаружено.

Docker API в этой сессии недоступен. PostgreSQL-проверка конкурентных
изменений не выполнялась; unit-тест проверяет лишь запрошенные параметры
изоляции. Очередь Trigger.dev, авторизованный production и реальные мобильные
устройства не проверялись. GitHub и сайт не изменялись.

Следующий конечный контроль — настоящая локальная БД: одновременная правка
между SELECT и пересборка нового документа после правок. Он не заменяет
оставшуюся независимую приёмку исходного обмера.

## Повтор 4 октября: реальная конкурентная правка и пересборка

Docker стал доступен. Создан отдельный контейнер `domitsa-export-snapshot-20261004-pg`
из уже установленного `pgvector/pgvector:pg17`, порт `127.0.0.1:55442`, база
`exportqa`. Данные находились в tmpfs, внешние тома не подключались. Миграции
применены только к этой базе. Чужие контейнеры и образы не менялись.

Добавлен `apps/web/lib/pdf/snapshot.integration.test.ts` с двумя сценариями:

- Writer удерживает `ACCESS EXCLUSIVE` на `rooms`; экспорт успевает прочитать
  проект и блокируется на комнатах. Ожидание подтверждается `pg_stat_activity`,
  а не предположением после задержки. При наблюдении очищается кеш статистики
  транзакции через `pg_stat_clear_snapshot()`. Writer атомарно меняет геометрию
  400 → 500 см, комнатные мерки, высоту и положение товара. После commit
  старый снимок остаётся согласованным; следующее чтение целиком новое.
- Правки кухонного модуля, его зон, поворот стула и дробные мерки сохраняются
  в PostgreSQL. Повторное чтение, комнатная раскладка, общий объём и PDF
  сверяются по данным. После удаления товара/модуля и очистки высот новая
  сборка оставляет контур, но не старые зоны, покупки или вертикальные мерки.
  Уже собранный HTML старого документа не изменяется.

Чувствительность конкурентного теста проверена отдельно: временная замена
repeatable-read на read-committed дала ожидаемый FAIL — старый проект 400 см
прочитался с новой шириной комнаты 500 см. Подмена удалена; повторный прогон
всех трёх целевых интеграционных файлов прошёл: 9 тестов. Unit-набор PDF,
apartment-volume и plan-volume: 67 тестов; типы web и scoped Biome прошли.
Полный набор 2118 unit-тестов и сборка относятся к предыдущему прогону,
в этой пачке они не повторялись: production-код остался прежним.

Повтор тестов: задать локальное окружение (без production .env и AI-ключей),
из `apps/web` выполнить `bun run vitest run --config vitest.integration.config.mts
lib/pdf/snapshot.integration.test.ts lib/projects/plan-scene-save.integration.test.ts
lib/projects/apartment-volume.integration.test.ts`. Для контрольной печати
дополнительно задать `QA_PRINT_PDF=1`; без флага тест не создаёт PDF.

Production-функцией `printPdf` напечатаны два шестистраничных QA-документа
`output/pdf/qa-snapshot-edited.pdf` и `output/pdf/qa-snapshot-removed.pdf`.
Все 12 страниц отрендерены Poppler и просмотрены: текст, дробные мерки,
известные/неизвестные высоты и схемы читаются, обрезаний не обнаружено.
Poppler повторил предупреждение `Bad bounding box in Type 3 glyph`;
визуального дефекта на страницах не найдено. Это внутренние QA-артефакты,
не пользовательские проекты и не подтверждение инженерной приёмки.

Этот прогон не запускает браузерный путь сохранения, очередь Trigger.dev,
S3 или production; проверяет PostgreSQL → текущие расчётные данные →
HTML → реальную печать PDF. Ранее записанные ограничения очереди и независимой
приёмки обмера остаются. GitHub и опубликованный сайт не изменены.
