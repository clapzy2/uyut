Повторяемая бесплатная проверка:

```powershell
cd C:\Users\Lenovo\Desktop\Room_project\apps\web
bun run scripts/qa-independent-pdf-corpus.ts 'C:\Users\Lenovo\Documents\Codex\2026-09-26\1-pdf-1-2-pdf-3\outputs'
```

Она сверяет SHA-256, выбранную страницу, нативный слой и сохранённые текстовые метки.
Для Басманного **3/3 печатных цепочек** сходятся арифметически. Из них **2/3**
подтверждены непрерывными нативными размерными линиями: верхняя 9655 мм и правая
7135 мм дают один масштаб в двух направлениях, включая все отдельные сегменты.
Нижняя цепочка 9655 мм не прошла автоматическую привязку: подпись короткого сегмента
`170` смещена в область соседней линии, результат `reused-dimension-line`.
Её нельзя молча засчитать как доказанную. На Basis и Рязанском подтверждено ещё по
**четыре отдельные линии** с одним масштабом в каждой странице. На Life метка
`3500` читается, но строгая привязка к нативной линии даёт
`no-connected-dimension-line`; у петербургского PDF текстовый слой отсутствует.
Это разные технические причины остановки, а не доказательство того, что файл
«плохого разрешения». Получено 5/5 источников; неподтверждённые мерки не подставлены.

Проверка нативных цепочек ещё не привязывает их концы к подтверждённым стенам,
не заменяет натурный обмер и не создаёт готовую 2D-квартиру. Скрипт намеренно не
присваивает типы комнат, которых нет на исходных листах.

На самих чертежах есть ограничения источника: Басманный обмер выполнен без отделки;
Basis — с частичной отделкой; Life — по черновым замерам подрядчика; Рязанский
требует уточнить все размеры при работах. Поэтому даже полная цифровая разметка
не сможет обещать точное соответствие построенной квартире без контрольного обмера.

Следующая пачка: взять Басманный как тест открытой оболочки без искусственных комнат;
затем размечать стены и проёмы на Рязанском с подтверждением каждой независимой
мерки. Петербургский альбом останется отдельным тестом для конвертированного в
контуры текста. Проектные изменения в исходную 2D-геометрию не подмешивать.
