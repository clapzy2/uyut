# Восстановление генерации и PDF, 14 ноября

Один пакет, без реальных генераций, экспорта и оплаты. Очередь в тестах
подменена, обрывы браузерных запросов создаются до отправки на сервер.

## Исправлено

- PDF атомарно занимает проект перед запуском. Восемь конкурентных запросов
  получают одну запись, только её создатель отправляет задачу.
- Запрос очереди использует ID экспорта как ключ идемпотентности и точную метку.
  Потерянный runId восстанавливается по метке без нового запуска.
- Сеть, 408/409/5xx и сбой сохранения runId/выдачи токена не считаются отказом
  принятой задачи. Интерфейс требует проверки статуса перед повтором.
- Ошибка аудита не превращает успешный запуск в отказ.
- Возраст записи больше не гасит живую очередь. Чтение одного PDF и списка
  одинаково сверяется с очередью. Недоступный статус явно помечается неизвестным.
- При конечном статусе освобождается только незавершённая запись. Если воркер
  уже сохранил PDF, перечитывается готовый результат вместо ложной ошибки.

Защита генерации уже реализована: атомарная бронь комнаты, метка/idempotency,
снятие только после конечного статуса, сохранение готовых концептов. Она не
переписывалась; добавлена проверка браузерного восстановления.

## Ограничение и следующий шаг

Если запись осталась до отправки в очередь или относится к старой версии без
runId/метки, отсутствие результата поиска не доказывает отказ. Она остаётся
неподтверждённой и может потребовать операционной сверки. Автоматический новый
платный запуск в таком случае намеренно не разрешается.

Общая оценка около 75%, финальная приёмка 60% остаются без изменения. Это
закрытие проверяемых отказов, а не независимый пользовательский пилот.
Расходы на модели $0. Физический телефон и реальные сбои провайдера не проверены.
