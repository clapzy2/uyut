# Проверка плотного растрового плана AKZENT

Исходник: [авторский JPEG DYNAMIC DESIGN, лист 2](https://static.tildacdn.com/tild3132-6132-4639-b936-356264363863/______-4.jpg), 1680 × 1187 пикселей, SHA-256 `1015bd3030f6918341f96d729861b212288ed918d480bd4d1b87ec0b8f0bc5a6`. Балкон №9 явно выступает слева. Его строка «2.0» в экспликации не доказывает ни площадь, ни границу пола.

| Проверка | До | После этой правки |
| --- | --- | --- |
| Исходный JPEG | 0 углов и отрезков; весь ответ отброшен после лимита 120 000 пиксельных рёбер | 853 угла, 568 отрезков из завершённых контуров чернил; `truncated=true`, `uncertain=true` |
| JPEG качества 60 | 0 | 957 углов, 662 отрезка; неполный набор |
| Поворот на 90° | 0 | 534 угла, 364 отрезка; неполный набор |
| Отражение | 0 | 856 углов, 572 отрезка; неполный набор |

На оригинале среди подсказок видны сторона у левого края выступающего балкона около `(190, 495)–(190, 697)` и верхний участок `(190, 495)–(256, 495)`. Это координаты **границы краски**, не метрический обмер и не классификация стены или пола. В том же ответе есть подписи, размеры, штриховка и таблица. Из-за плотности изображения ответ остаётся неполным: отсутствие другой стороны не является свидетельством отсутствия стены.

Теперь сервер оставляет только замкнувшиеся исходные контуры до лимита; оборванный лимитом контур не замыкается искусственно. Ручной редактор может предложить их углы лишь после явного запроса, сверки SHA/листа и включения помощи при обводке. Предупреждение сообщает о неполноте. Одна подсказка не создаёт подтверждённый контур, комнату, проём или 3D.

Воспроизведение без AI, аккаунта и загрузки в хранилище: `bun run apps/web/scripts/bench-raster-edges.ts <JPEG> <каталог>` из корня репозитория. Локальные наложения и JSON сохранены вне Git в `tmp/raster-control-2026-10-18/edges-partial/`. Синтетические положительные и отрицательные регрессии проверяют, что завершённый прямоугольник сохраняется при переполнении, оборванная полоса не замыкается, а шумовая шахматная сетка не становится контуром.

**Остаток:** по этому JPEG нельзя автоматически назвать пиксельные линии физическими границами пола или косяками и перенести размеры/высоты в 2D/3D/PDF. Требуется сверка человеком на исходнике и исходный масштаб/обмеры. Никакой площади балкона из таблицы эта правка не переносит.
