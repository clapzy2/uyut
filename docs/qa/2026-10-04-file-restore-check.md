## Изоляция и очистка

Использованы уже имеющиеся Docker-образы, без pull/установки. MinIO работал
в отдельной `--internal` сети, без опубликованных портов и постоянных томов,
с read-only rootfs и tmpfs `/data` 64 МиБ. Клиент работал в той же сетевой
области с отдельными тестовыми ключами; папка источника монтировалась read-only.
Обращения к рабочему S3 из этой области невозможны. Точные ID и UUID-метки
проверялись перед удалением. Свои временные контейнеры и сеть удалены;
чужие Docker-ресурсы не затронуты. Маленькая контрольная копия и отчёт сохранены.

Первый запуск локального HTTP через опубликованный порт internal-сети не дошёл
до восстановления: Docker Desktop не передал этот трафик. Временные ресурсы
того запуска удалены. Успешный запуск использовал клиент внутри сетевой области
хранилища; изоляция не ослаблялась и рабочий сервер не менялся.

Приватные артефакты (ignored, не публикуются):
`tmp/file-restore-20261004/source/manifest.json`, четыре `.bin`, `report.json`
и второй `report-8ebb09aacd534f2d.json` (первый отчёт не перезаписывался).
Имена рабочих S3-ключей, URL, ключи доступа и содержимое файлов в этот отчёт
не включены. Хеши конкретных файлов доступны в локальном JSON.

## Повторяемая проверка

Скрипт: `jobs/scripts/check-file-restore.ts`. До первой S3-записи он проверяет
полный набор, обычные файлы без symlink, размеры и SHA-256. Один файл ограничен
64 МиБ, весь набор — 128 МиБ. Разрешён только явный loopback endpoint с портом
и новый бакет вида `domitsa-restore-<16 hex>`. Рабочий endpoint из `.env` не
используется; нужны отдельные `RESTORE_S3_ACCESS_KEY` / `RESTORE_S3_SECRET_KEY`.
ACL не расширяется, исходники не меняются, автоматического удаления/повторов нет.

Пример **в уже проверенном изолированном хранилище**, не на production:

```powershell
bun run jobs/scripts/check-file-restore.ts `
  C:/отдельная-копия/manifest.json `
  http://127.0.0.1:9000 `
  C:/отдельная-копия/новый-отчёт.json
```

Manifest версии 1 содержит ровно plan/render/mask/pdf: `kind`, `file`, `bytes`,
`sha256`, `contentType`; файлы — `plan.bin`, `render.bin`, `mask.bin`, `pdf.bin`.
В манифест не нужны рабочие ключи объектов. 20 целевых тестов проверяют неверную
цель, неполный/подменённый набор, путь, тип, лимиты, порчу, усечение и каталог
вместо файла; весь unit-набор — 2485 тестов в 197 файлах, типы семи пакетов
и lint прошли.

## Граница результата

Это не подтверждает независимую долговременную копию всего бакета, ежедневную
передачу и ретеншен, восстановление после потери аккаунта хранилища или доступы
владельца в аварии. Отсутствие BACKUP_BUCKET в окружении web не доказывает,
что резервирование не настроено отдельно в Coolify. Отдельная read-only проверка
API базы подтвердила включённое ежедневное расписание с сохранением в S3 и пять
успешных запусков 30 сентября — 4 октября; чтение резервного S3-объекта этим
не проверено. При настоящем восстановлении
нужны полный manifest и копия, соответствующие сохранённой базе; нельзя
перезаписывать пользовательские объекты ради теста.
