## Исправлено и проверено

- CSV собирается участками строк, а не посимвольным склеиванием.
- Импорт идёт пачками по 200 строк через временную таблицу одной транзакции.
  Первые данные модели и порядок вариантов сохраняются; вариантов не больше 24.
  Скрытие отсутствующих товаров происходит только после полного чтения.
- Обрыв сети, незакрытые кавычки и пустой фид откатывают импорт. Предыдущий
  каталог не заменяется неполным ответом. Без внешнего контрольного количества
  строк CSV сам по себе не доказывает, что партнёр выгрузил весь ассортимент.
- Ткани Askona с меняющимся skuId объединяются только при том же productId
  и одинаковых явно указанных ширине/глубине; известная высота входит в ключ.
  Неизвестные мерки не используются для такого объединения.
- Дробные размеры CSV/YML/текста сохраняются. Явные мм и см имеют приоритет
  перед эвристикой; 2105 мм остаются 210,5 см, а не 211 см.
- Явная готовая пометка `ad_disclosure` сохраняется целиком, если источник
  передал её. Из бренда, описания или erid в ссылке пометка не выдумывается.

остаются в игнорируемой папке QA; публичная фикстура содержит только вымышленные
магазины/ссылки. API-поиск является выборкой, а не полным ассортиментом.

У 40/40 товаров есть готовая пометка в `tagging_ads/info`, включая рекламодателя,
ИНН и erid. Старый разбор её терял, новый сохраняет. Исправления контракта:

- Текущая и старая цена сохраняют копейки; общая функция CSV больше не стирает
  десятичную точку. Пробелы, запятая и обозначение рубля проверены отдельно.
- Две SKU с общим артикулом не исчезают из-за порядка параллельных запросов.
  Новый ключ включает id сети. Ранее выбранные товары не удаляются и не переписываются;
  перед массовой production-загрузкой отдельно проверяется переход со старых ключей.
- CDATA-картинки, второй снимок, XML-сущности, отдельный merchant_id и валюта
  проверены. Готовая пометка не восстанавливается из бренда или ссылки.
- Выделенные параметры и извлечённые из описания мерки различаются по каждой оси.
  Повторный импорт CSV не меняет эту метку и не восстанавливает отвергнутый размер.
- Размер спального места или неоднозначная пара в названии кровати не выдаётся
  за внешнюю раму. После консервативной проверки габариты есть у 11/40 товаров,
  а не у 16/40. Недостающие числа не заполняются.
- Реальная строка `3 ящика,1200×450×760 мм` больше не превращается в 45×76 см:
  запятая без пробела распознаётся, чтение с середины тройки запрещено.
- Неудачные страницы делают сбор неполным с ненулевым кодом завершения. Такой

## Ночное обновление Gdeslon: следующая пачка

Ручной CSV и worker используют один сборщик. Пагинация ограничена 1–12 страницами,
тремя запросами одновременно и четырьмя минутами. Некорректный XML или отказ
авторизации не принимаются за пустой ассортимент; наружу выводятся только счётчики,
без URL с ключом. Товары без готовой пометки не публикуются.

Запись полностью полученной выборки атомарна. Любая неудачная страница запрещает
запись этой пачки; отсутствующие в поиске товары не скрываются. Старые UUID,
связанные покупки, ручные размеры и координаты не удаляются при переходе ключей.
Старые строки не получают новую дату синхронизации без ответа API.

Добавлена задача `refresh-gdeslon-catalog`, общая с ночным `index-catalog`.
До отдельного включения `GDESLON_REFRESH_ENABLED=1` она ничего не импортирует.
Ночной запуск остаётся в 03:00 UTC / 06:00 Москвы. На векторизацию выделяется
оставшееся время родителя с запасом; ручной пересчёт можно ограничить одним
источником. Подбор больше не использует прежний вектор после изменения товара:
`embeddedHash` должен совпадать с `contentHash`.

Локально прошли 2342 unit, typecheck семи пакетов, lint 722 файлов,
15 интеграционных проверок каталога. Три новые проверки подтверждают сохранность
старой покупки, идемпотентность, отказ при неполной выдаче и необходимость
пересчёта изменённого изображения/текста. Production baseline: 3227 записей
Gdeslon, ни одна не свежая. Это не закрытие рабочего подбора: живая приёмка
новой задачи и векторов выполняется после выкладки.

Production-сборка прошла. Обнаруженный локально конфликт браузерного импорта
`node:timers/promises` устранён до отправки: ожидание отменяется стандартным
таймером без серверной зависимости в общем модуле AI.

Лимит векторизации действует внутри сетевой пачки: общий AbortSignal передаётся
загрузке картинки, приватному S3, запросу Voyage и ожиданию повторов. Прерванная
пачка не сохраняет векторы/хеш. Четыре теста срока покрывают обрыв скачивания,
обрыв расчёта, нулевой бюджет и отмену длительного ожидания после HTTP 429.
Независимый read-only обзор не нашёл оставшихся
P0/P1 в изменённом контракте. Это не утверждение, что любой CDN отдаёт картинки.

Gate: блокирующих ошибок локальной пачки не найдено. Для закрытия пакета 4
нужны успешный live-refresh, сохранность прежних строк, готовые векторы и
реальный запрос подбора. Важные ограничения: API — выборка; отсутствие
габаритов не заполняется; недоступные картинки не считаются принятым image-поиском.

Браузерная проверка существующего опубликованного концепта кухни показала цены,
магазины и пометки. Не добавляли товары в пользовательский список. Найдена P1:
«Оптима, 600×760×900 мм» назначалась осям 60/76/90; при участке 85 см `checkFit`
возвращал положительный ответ без доказательства порядка осей.

В исправлении сборщик принимает только подписанные параметры Gdeslon. CSV
сохраняет `dimensions_checked`, поэтому повторно не угадывает пустые оси по
названию. Общий `effectiveSizeReading` также исключает текстовые/неизвестные
оси старых Gdeslon-записей, не изменяя их БД и не трогая ручные мерки. Этот
контракт используется в карточке концепта, покупках, 2D, PDF и задании рендера.
