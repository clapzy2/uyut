# Правки 2D и повторное открытие 3D

Дата: 3 октября 2026. Проверка локальная. Мерки заданы для синтетического
сценария; точность распознавания опубликованной квартиры этим не подтверждена.
Изменения не отправлены в GitHub по просьбе владельца.

## Исправление

При замене модели на том же canvas прежняя сцена принудительно теряла
WebGL-контекст. Следующий экземпляр Three.js не открывался: воспроизведена
ошибка чтения `precision` у `null`. Теперь замена освобождает геометрию,
материалы, обработчики и renderer, но сохраняет контекст того же canvas.
При закрытии просмотра контекст освобождается, как раньше.

Готовность и ошибка привязаны к конкретной модели, а не ко всем последующим
планам. При смене модели выделение сбрасывается. После некорректной модели
новая корректная модель снова открывает сцену; настройки просмотра сохраняются.

## Три отдельных уровня проверки

| Уровень | Что проверено | Что не проверено |
| --- | --- | --- |
| JSON и построение сцены | Новая высота стены, положение и вертикали окна, удаление высот, изменённый контур с прежним габаритом, исключение устаревшей мебели. Исходные объекты не меняются. | Запись в базу и браузер. |
| Настоящая локальная PostgreSQL | Создание проекта, запись исходного плана, повторная запись правок и чтение через существующий repository. После чтения пол имеет ширину 500 см, стена 310 см, окно — смещение 200 см, низ 95 см и высоту 140 см. Очистка высот остаётся очисткой после чтения. | Server actions, авторизация браузера, очередь, production. |
| Браузер с рабочим компонентом | Смена ширины 400 → 500 см и стены 270 → 300 см, сброс выделения, удаление мебели, отказ некорректного источника и восстановление, повторное открытие JSON из localStorage после перезагрузки, восстановление на новой модели после события потери контекста. | Это временная локальная страница с синтетическими данными, не полный маршрут реальной квартиры. localStorage не выдаётся за серверное сохранение. |

Браузер проверен при ширине 1440 и 390 px. На телефоне горизонтального
переполнения нет, управление переносится на следующие строки, canvas виден
в полном снимке страницы. В конце — 0 ошибок и 0 предупреждений консоли.
Режим Chromium использует программный WebGL; реальный телефон и его GPU
этим не проверены.

## Автоматические проверки

- 1938 тестов веб-приложения прошли в 155 файлах, включая шесть локальных
  контролей исходного PDF Ребриной. Без этого локального PDF они явно пропускаются.
- 16 интеграционных тестов прошли: 14 существующих проверок редактора и
  две новые проверки сохранения геометрии для 3D.
- Проверка типов, сборка приложения и Biome для семи изменённых файлов прошли.
- Проверка различий не обнаружила ошибок пробелов.

Интеграционные тесты выполнялись в отдельном контейнере
`domitsa-scene-revision-qa-20261003`, с временным хранилищем в памяти,
только на `127.0.0.1:55437`. Рабочая база не использовалась.
После проверки удаляются только этот контейнер и временные помощники браузера.

Полезные снимки сохранены локально:

## Граница результата и следующая пачка

Исправлена стабильность просмотра после правок, а не точность чужого обмера.
Полный точный 2D опубликованной квартиры и production остаются непринятыми.
Новые источники имеют отдельные отчёты:
[PDF Ребриной](2026-10-03-rebrina-existing-control.md) и
[DWG INT LINES](2026-10-03-dwg-existing-control.md).

Следующая пачка: поддержать проверку наклонных размерных цепей без усреднения
стен до прямоугольника; подготовить явно производный PDF текущего слоя DWG
для координатного контроля существующего PDF-маршрута. Не достраивать
неизвестные высоты и не закрывать разрыв контура по догадке.

## Дополнение 4 октября: проёмы и кухонные зоны

Закрыта отдельная пачка переноса существующих данных в объём:

- Исходная камера WebGL учитывает не только поверхности, но и линии стен
  и проёмов. Регрессия сначала воспроизвела выход верхней грани окна за кадр
  (`y = 1.187` в нормализованной проекции), затем прошла при 1000 и 390 px.
- PDF-доказательства участков стен могут оставлять разрыв на месте проёма.
  Проём теперь переносится целиком один раз по актуальной привязке исходника,
  отдельно от участков стен. Нет новой стены или перемычки через неизвестный
  разрыв. Изменение ширины после доказательства по-прежнему делает его устаревшим.
- Кухонные рабочие и монтажные зоны перенесены без списка покупок и остаются
  в общей модели квартиры. Неполные эксплуатационные мерки дают предварительную
  зону из известных данных, а не подставленный стандартный запас.
- SVG показывает заданный низ и высоту проёма даже при неизвестной высоте стены;
  после очистки высоты остаётся только положение на полу, как в WebGL.

### Проверки и границы

2114 тестов веб-приложения в 166 файлах, семь целевых интеграционных тестов
сохранения сцены и общей модели квартиры, типы web/catalog/jobs, production
build, scoped Biome девяти изменённых файлов и `git diff --check` прошли.
Интеграционные тесты использовали отдельный контейнер
`domitsa-volume-acceptance-20261004-pg`, `127.0.0.1:55441`, tmpfs без постоянного
тома. Тест сохранения сцены теперь отказывает при нелокальном DATABASE_URL.

В браузере проверены настоящие компоненты на временном синтетическом стенде:
1440 и 390 px, выбор мебели и сброс выбора после смены модели, перенос модуля,
удаление его высоты, переключатель зон, очистка высоты окна, удаление модуля
вместе с его зонами, перезагрузка сохранённого в localStorage состояния.
Canvas остаётся рабочим, SVG согласован с теми же данными; при 390 px ширина
документа также 390 px. Высокое окно полностью видно в обоих представлениях.
После настройки временного стенда консоль: 0 ошибок, 0 предупреждений.
Программный WebGL Chromium не заменяет проверку GPU реального телефона.
Этот стенд не проверяет авторизацию и server actions; запись в БД проверена
отдельным тестом repository и не подменяется localStorage.

Снимки: `output/playwright/volume-acceptance-20261004/desktop.png`,
`mobile-high-opening.png`, `mobile-empty.png`. Временные исходники стенда,
его процесс и только собственный QA-контейнер удалены после проверки.
Рабочая БД, сторонние контейнеры, GitHub и сайт не менялись.

Полная точность неизвестного обмера не объявлена достигнутой. Следующая
конечная пачка — согласованность экспорта с последней проверенной геометрией,
высотами и кухонными зонами; условия независимой приёмки остаются в roadmap.
