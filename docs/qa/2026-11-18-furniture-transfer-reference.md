# Перенос исходной мебели: образец с фото

Статус: локальная подготовка, критерий сохранения предмета НЕ выполнен. На сайт не выложено, коммитов и PR нет.

## Воспроизведение

На пользовательской кухне одношаговые варианты переносили комод под окно, но меняли расположение ящиков и ручки. Первичный keep-путь не использовал существующий пошаговый рендер и не передавал отдельный образец предмета. Детектор товаров кухни не ищет комоды; его категории не расширялись.

## Подготовленный код

- Выделение рамки предмета на исходном фото независимо от товарных меток; выбор двух противоположных углов.
- Рамка привязана к photoRevision, проверяется владельцем серверного действия и повторно воркером. Клиент не передаёт ключ хранилища.
- Планирование выполняется под блокировкой комнаты. Один образец разрешает только один шаг установки с needsObject; неоднозначный или слишком длинный план отклоняется до очереди, бронь освобождается.
- Вырезка исходного предмета готовится один раз на запуск. При удалении образец не прикладывается, при установке передаётся отдельной картинкой с указанием сохранить фасады, ящики, ручки и пропорции.
- Потеря образца прекращает цепочку до первого платного рендера. Для старого пути правки концепта отсутствие выбора предмета возвращает сообщение до запуска.
- Новое выделение запускает один вариант с максимум четырьмя шагами, а не три цепочки. Обычные генерации и перекраски без выделения сохраняют прежний путь.

Браузерное взаимодействие с новым выделением и серверная запись нового пути не проверены: Docker Desktop сейчас не запущен. Production не изменялась.

Один планировщик и одна цепочка из четырёх рендеров: убрать стулья, убрать исходный комод, сдвинуть холодильник, поставить комод с образцом. Повторных платных рендеров нет. Первый завершённый файл не скачивался Bun-клиентом; тот же оплаченный результат получен повторным GET через PowerShell. Остальные шаги использовали тот же обход скачивания только в локальном QA-скрипте. Продуктовый сетевой код не менялся.

### Локальная проекция без платных запросов

Подготовлен изолированный локальный `tmp/project-source-face-prototype.ts`: обратная гомография видимой плоскости, билинейная выборка из оригинала, замена ремонтного фона только внутри явных четырёхугольных областей, PNG без потерь. Проверяются границы фото, выпуклость, вырождение, отражение, совпадение разрешения и лимит пикселей. В продуктовый генератор модуль пока не включён.

56 профильных тестов прошли, включая тождественное преобразование цветной сетки, побайтовое совпадение фона вне разрешённых областей, отказ на пересечении/отражении/коллинеарности/NaN/другом разрешении. Типизация всех 7 пакетов прошла. Это не проверка эстетики или метрического размещения.

На этой кухне создан `pixel-transfer.png`, разметка пиксельная ручная и сохранена отдельно. Ручки берутся из оригинала, но при сильном развороте видны растяжение, перспективные искажения объёмных ручек и стыки фоновых заплаток. Критерий аккуратного готового изображения по-прежнему НЕ пройден. Исходник снят сбоку и не позволяет получить недостающие поверхности без реконструкции/догадки. Следующий полезный вход — фронтальный кадр самого комода; он улучшит данные для фасада, но не гарантирует качество всей 3D-перестановки.

Новых платных запросов в этом продолжении: 0. Коммитов, PR и выкладки нет. Не показывать технический монтаж как готовую функцию сайта.

Не выкладывать это как исправленный точный перенос. Для гарантированного сохранения видимых деталей нужен путь с сохранением исходных пикселей и явной геометрией поверхности/маской, а не очередное усиление текста для генератора. Фронтальный снимок комода даст сведения о плохо видимых фасадах, но сам по себе не гарантирует соблюдение их генератором. Перед дальнейшими платными опытами проверить локально управляемое преобразование и сохранение фона; не запускать одинаковые серии с усиленными промптами.
