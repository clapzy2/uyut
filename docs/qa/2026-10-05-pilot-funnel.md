# Минимальная воронка пилота — 05.10.2026

## Что реализовано

Существующий PostHog используется без новых сервисов, таблиц и зависимостей. Вместо
полных URL и параметров отправляется одно событие `pilot_stage_viewed`, версия 1,
с фиксированным типом открытого экрана:

`landing`, `registration`, `login`, `projects`, `onboarding_1`–`onboarding_5`,
`project`, `room`, `concept`, `summary`.

Для пилота можно собрать в PostHog воронку «старт → квартира → комната → концепт →
итоги», фильтруя каждый шаг по `stage`. Новая квартира может появиться без полного
прохождения анкеты; возвращающийся пользователь может начать с комнаты. Поэтому
непрохождение всех пяти шагов анкеты само по себе не является ошибкой.

Просмотр итогов **не означает** скачивание PDF, а просмотр концепта не доказывает
успешную генерацию, выбор варианта или сохранение. Оплата, ручные поправки размеров,
переключение вкладок 2D/3D и исходы фоновых задач этой воронкой не измеряются.
События результатов действий не добавлены: для них нужны отдельные подтверждённые
сигналы, а не предположение по адресу страницы.

## Приватность и отказоустойчивость

- Нет URL, строки запроса, фрагмента, реферера, идентификаторов квартиры/комнаты/
  концепта, имён, почты, заметок, размеров, изображений и содержимого плана.
- Последний фильтр `before_send` допускает только указанное событие, фиксированный
  этап, версию и служебные анонимные UUID PostHog. Публичный ключ проекта PostHog
  сохраняется как необходимое транспортное поле, а не пользовательский токен.
- Профили пользователей, автозахват, запись экрана, pageview/pageleave, опросы,
  загрузка расширений и feature flags отключены. Источники перехода и рекламные
  параметры не сохраняются. Сеть по-прежнему неизбежно видит адрес подключения;
  обещание «полностью анонимно» здесь неприменимо.
- DNT и Global Privacy Control проверяются до загрузки SDK и перед отправкой.
  Сохранённый штатный отказ PostHog продолжает обрабатываться самим SDK. Новая форма
  согласия не добавлялась; используются существующие правила приватности проекта.
- Неизвестные экраны, приглашения и восстановление пароля не отслеживаются.
- Быстрый переход или размонтирование во время импорта не отправляет устаревший
  экран. При блокировке счётчика работа сайта продолжается.

Анонимный идентификатор браузера не связывается с аккаунтом. При очистке cookie,
смене браузера или блокировке аналитики один человек может учитываться иначе или
не учитываться вовсе. Это наблюдение пилота, не достоверный подсчёт клиентов.

- Biome на четырёх изменённых файлах: **успех**. `git diff --check`: **успех**.

Дополнительно настоящий SDK 1.428.3 проверен в Chromium на локальном сайте с
фиктивным публичным ключом и перехватом запроса, без отправки провайдеру.
Gzip-нагрузка версии `16ddced` разобрана: одно `pilot_stage_viewed`, stage `concept`; только
stage/funnel_version/token/distinct_id/$session_id/$window_id/$process_person_profile.
Контрольный параметр ссылки, UUID проекта/комнаты/концепта и адрес страницы
отсутствуют. При DNT=1 запросов за контрольные 5 секунд нет, страница работает.
Обычный headless UA отбрасывается самим SDK как bot; сетевой контроль выполнен
с обычным мобильным UA, не отключая защиту SDK в приложении.
Текст политики обновлён под фактический состав событий и DNT/GPC: запрет только
сторонних cookies не выдаётся за отключение first-party счётчика.

После публикации `16ddced` на настоящем QA-концепте декодирован gzip-запрос
к фактическому `https://eu.i.posthog.com/e/`: одно `pilot_stage_viewed`, stage
`concept`, только разрешённые поля. После проверки запрос продолжен, приёмник
вернул HTTP 200. Это подтверждает принятие коллектора, не просмотр отчёта в
аккаунте PostHog и не статистику реальных пользователей. Первый диагностический
перехват ожидал другой путь `/i/v0/` и не сработал; фактический приёмник найден
в сетевых запросах, контроль повторён на нём. Ошибки приложения из этого нет.
Проект PostHog в аккаунте сверен с ключом production-сайта. В Activity видны
два тестовых события `pilot_stage_viewed` с этапом `concept`, без URL и данных
квартиры. Сохранён [отчёт по пяти экранам](https://eu.posthog.com/project/268829/insights/dIEHbrZM)
с окном перехода один день. Полного прохождения маршрута ещё не было, поэтому
отчёт пуст; тестовые события не считаются результатом независимого пилота.

Обнаружено, что при включённом в настройках PostHog сбросе клиентского IP
сервис всё равно добавлял к QA-событию геоданные по сетевому адресу. В фильтр
`before_send` добавлен `$geoip_disable: true` для каждого разрешённого события.
Исправление `35cdb2b` прошло CI и опубликовано. Новое событие `stage=landing`
появилось в Activity с `GeoIP disabled = true` и без полей города, страны или
координат. Ранее собранные QA-события этим изменением не очищаются.
Выводы о физических телефонах и независимом новичке из этих тестов не следуют.
