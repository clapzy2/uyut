## Стенд и критерии

Используются уже сохранённые серверные образы, без pull и установки. В отдельную
базу восстанавливается проверенный custom-архив 37 101 107 байт, SHA-256
`76535753885d7a00de288c99a8bb53a3bf76db983d894d4cd3a91a532faa53fe`.
Это историческая контрольная копия, не свежий снимок текущего сайта.

Контейнеры принадлежат только этому прогону: UUID-метки и точные ID, отдельная
internal-сеть, без опубликованных портов и постоянных томов, read-only rootfs,
tmpfs и лимиты памяти. Рабочие ключи AI, платежей, SMTP и Trigger не передаются.
Обычный CMD миграций обходится: запускается только сервер приложения.

В копии создаются отдельные синтетические владелец, партнёр, посторонний,
квартира, комната и товар. Проверяются настоящие HTTP-вход и сессия, три маршрута
(проект/комната/итоги) для четырёх ролей, запрет партнёру и постороннему менять
количество покупки, сохранение дробных мерок и количества владельцем через
server actions. После каждого переключения
сверяются журнал миграций и контрольные суммы бизнес-таблиц. Разрешённые изменения
только в синтетических комнате, покупках и времени обновления их проекта не
выдаются за потерю данных. Исходные строки копии отдельно сверяются без фикстуры.

## Исправления самого стенда

Первый запуск остановился до HTTP-приёмки: временный harness искал Argon2-модуль
по отсутствующему пути в standalone-образе. Для синтетического пароля использован
уже установленный локальный `@node-rs/argon2`; настоящий вход не обходится.
Задержавшееся удаление Redis перепроверено по полному ID: все свои ресурсы удалены.

Второй запуск остановился на HTTP 500 при входе. После очистки отдельно проверены
только Redis/DNS, без базы и архива: полное имя Redis HTTP-контейнера длиной 64
символа даёт `ENOTFOUND`, короткий alias `srh` — DNS resolved, HTTP 200 и PONG.
Проверка закончилась в 21:00:53 Москвы; свои три контейнера и сеть удалены.
Имена QA-контейнеров сохраняют UUID, адреса внутри сети используют короткие aliases.
Этот диагностический результат не выдаётся за успешный откат приложения.

Следующий прогон прошёл вход, но остановился на слишком строгом ожидании HTTP 404
для постороннего. Для потокового ответа Next.js допускает HTTP 200 с экраном
not-found; [официальный контракт](https://nextjs.org/docs/app/api-reference/file-conventions/not-found).
Флаги содержимого в том запуске не сохранялись, поэтому по этому HTTP 200
не утверждаются ни утечка, ни корректный отказ.
Проверка прав должна требовать реальный экран отказа и отсутствие маркеров
синтетической квартиры/комнаты, а не принимать любой HTTP 200 за доступ.
Анонимный переход проверяется как HTTP redirect либо подтверждённый потоковый
redirect в `/login`, также без раскрытия данных. Этот прогон сам по себе откат
не принял; свои ресурсы удалены.

Прогон с исправленным потоковым критерием остановился до восстановления базы
на `TimeoutExpired` при создании своей internal-сети. Новые стенды после этого
не создаются. Отсутствие ответа Docker нельзя считать отсутствием созданного
ресурса: очистка требует успешной сверки точного имени/ID, UUID-метки, internal
и отсутствия подключённых контейнеров. Настройки рабочего Docker не меняются.
Приватный отчёт этого запуска — `tmp/rollback-20261004/streaming/report.json`.

Очистка принята в 21:12:59 Москвы. Поздно созданная сеть найдена по точному
имени, затем сверены полный ID, UUID-метка, internal и отсутствие контейнеров;
удалён только этот ресурс. Свежая проверка всех пяти UUID прогонов показала
0 собственных контейнеров и 0 сетей. Docker 29.8.0 отвечает, публичный health
вернул HTTP 200; SHA-256 исходного архива неизменен. Итог —
`tmp/rollback-20261004/summary.json`. Полный откат остаётся непринятым.
