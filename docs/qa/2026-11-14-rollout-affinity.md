# Одна версия страницы на время выкладки

## Причина и границы исправления

При выпуске #300 наблюдался ChunkLoadError, пока одновременно работали два
контейнера. У обоих одинаковые имена Traefik-сервисов, а sticky cookie нет.
HTML и хешированный JS могут попасть на разные контейнеры. Повтор страницы
не гарантирует успеха, пока балансировщик продолжает смешивать версии.

Добавляется cookie domitsa_release только к пяти существующим HTTPS-сервисам
Домицы. Она закрепляет запросы страницы за одним контейнером; Secure, HttpOnly,
SameSite=Lax, область по умолчанию /. Cookie не содержит учётных данных.
Маршруты, домены, сеть, другие приложения и настройки общего прокси не меняются.

Это не хранение старых JS навсегда: после удаления старого контейнера старая
вкладка может потребовать перезагрузки. Существующая защита от устаревшей сборки
и ручной повтор остаются. Платные POST не повторяются автоматически.

## Локальная проверка

`node infra/coolify/check-rollout-affinity.mjs` запускает отдельный Traefik v3.6
и два nginx с несовместимыми именами JS, не подключаясь к рабочим приложениям.
Без закрепления 20/20 запросов JS возвращали 404. С закреплением 40 сессий,
120 запросов JS прошли с 200. Проверены флаги cookie и переназначение браузера
после удаления старого backend. Настройки перечитываются перезапуском только
тестового прокси, поскольку Docker Desktop не всегда доставляет файловые события.

Браузерный stale-build-recovery: 1 passed. Повтор заменяет документ без POST.
Результат HTTP-проверки не выдаётся за полный тест двух сборок Next.js.

## Применение

`infra/coolify/configure-affinity.ps1` работает только с UUID Домицы.
По умолчанию Plan ничего не меняет. Apply сохраняет резервную копию labels
и settings в tmp, добавляет cookie и временно включает consistent container name.
Первая выкладка выполняется stop/start: разные конфигурации одного Traefik-сервиса
нельзя накладывать друг на друга. Возможна короткая недоступность только Домицы.
После готовности новой версии ResumeRolling возвращает обычную поэтапную выкладку;
в последующих версиях labels одинаковы и допускают совместную работу контейнеров.
Команда API сама не запускает выкладку. Нельзя повторно Apply для каждого выпуска.

Для отката: восстановить custom_labels и значение consistent container name
из резервной копии через API приложения, затем выпустить его штатным способом.
Общий прокси не перезапускать. Результаты фактического выпуска записываются ниже.
