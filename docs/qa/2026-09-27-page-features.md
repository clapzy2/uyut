## Что реализовано

- Проёмы: дверь, окно, балкон; два нативных конца и явно выбранная сторона комнаты.
- Препятствия: шахта/короб, колонна, неподвижный объект; простой внутренний контур.
- Проверка точного членства узлов, полного вхождения в вогнутую комнату, непересечения,
  валидности стороны, лимитов и уникальных идентификаторов. Старые разметки без объектов работают.
- Свежие server-only `featureChecks`; браузер не может прислать проверенную ширину/индекс подписи.
- Нативная ширина на частичной стороне в обеих осях. Идентичные повторные операции учитываются
  без ложной неоднозначности; отличающиеся стрелки и ветви не выбираются автоматически.
- Request-local кеш верификатора. Более восьми потенциальных подписей — явная неоднозначность;
  множество конкурирующих стрелок не создаёт декартово произведение пар.
  Независимый пробник: 1000 подписей ≈2 мс; 2000 стрелок ≈24 мс, ширина не принята.
- Авторизация владельца, hash/page/state и атомарная версия сохранения остаются обязательными.
  Неверная разметка для повторного чтения отклоняется до платного вызова.
- Координаты листа не становятся автоматически глобальным планом в миллиметрах.
  Ни `confirmedAt`, ни метрическая геометрия квартиры не выставляются этой проверкой.

## Проверки

- Все 1207 тестов в 103 веб-файлах; typecheck всех семи пакетов; lint; production build.
- Независимый аудит серверной геометрии и свежего полного источника; открытых замечаний нет.
- Chromium, реальный PDF/JPEG/векторные узлы, реальные компоненты и серверные helpers.
  Сохранение QA только в памяти; server action/БД/хранилище production не вызываются.
- Правка точки скрывает старую ширину; неверная сторона отклонена с сохранением черновика.
- Сохранение/повторное открытие; удаление и повторное создание двери через точные координаты
  и явное принятие каждого узла; после сохранения кухня снова получает 900 мм.
- Незавершённая колонна блокирует сохранение; удаление требует подтверждения.
- Обрыв ответа и конфликт версии сохраняют точки; при конфликте повторное сохранение заблокировано.
- Ширины экрана 1280 и 390 px, обе темы, масштаб листа 200%; переполнения всей страницы нет.
  Нужная прокрутка увеличенного листа остаётся внутри его окна.
- Найден и исправлен конфликт React keys панелей выбора объекта и координат.
  После исправления ошибки консоли — только намеренные обрывы QA-запроса.
