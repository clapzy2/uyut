Три обращения, суммарный provider-reported cost **$0,245829**. Это usage провайдера,
не проверенный инвойс или текущий баланс. Запросы не повторялись автоматически.

Sonnet 5 вернул evidence на верхнем уровне вместо каждой комнаты. В шаблон добавлены
явные `measurementEvidence.width/depth/ceiling` и `ceilingEvidence`, пояснено расположение
объекта и запрещено двойное сложение общего размера, составляющих и толщины стены.
После изменения выполнен один новый контроль Sonnet 4.5, а не только бесплатный replay.

В третьем ответе ширина ванной №7 всё ещё **1954 вместо 1754 мм**. Числовая/текстовая проверка
сама по себе пропустила эту ошибку: подпись принадлежит другой цепочке. Геометрический gate
не принял размер. Это подтверждает необходимость принадлежности цепочки контуру, а не
ослабления parser ради большего числа заполненных полей.

Geometry gate использовал только ранее проверенные контуры №2/3/4: приняты ширины гостиной
3389 и спальни №4 2985 мм. Нет доказанных контуров остальных комнат — размер не подтверждается,
даже когда число совпадает с эталоном. Показатель 2/12 НЕ означает, что AI ошибся во всех остальных
числах. Все 12 сторон полной квартиры пока не подтверждены.

Качественные layoutNotes тоже ошибаются: кухня объявляется прямоугольной, окна/двери описываются
на неверных сторонах. Числовой gate не доказывает этот текст. Свободные числовые размеры уже
отфильтровываются; архитектуру следует сверять с подтверждёнными контурами и проёмами.
Один лист и по одному вызову не доказывают глобальную точность или причинность улучшения 10→11.
Производственная модель чтения не переключена на Sonnet 5.

## Рендеры

Четыре сценария: компактная кухня, спальня, гостиная, детская. Три модели, два независимых
повтора каждого задания: **24/24 изображения получены**, без повторной генерации.
Sunburst, Nano Banana 2 и Nano Banana Pro получили одинаковые исходник и актуальный template-
prompt внутри каждого сценария. Никаких эталонных размеров, crop или дополнительной инструкции
для одной отдельной модели не было. Детская использует фото спальни с новым назначением.

Бесплатные существующие источники: Lisa Anna / Pexels 19857231, Peter Vang / Pexels 35493898,
Alex Tyson / Unsplash ZWHajYLVsKo. Авторство, ссылка, лицензия, исходный SHA и точный prompt
сохранены в приватном manifest. Фото не являются подтверждёнными обмерами российской квартиры;
они проверяют сохранение видимой архитектуры, а не инженерные нормы.

Основной просмотр: все 24 изображения на четырёх листах; спорные кадры просмотрены целиком.
Дополнительный независимый просмотр всех 24 полноразмерных выходов проведён вслепую по номерам
1/2/3, без чтения соответствия номеров моделям. Размеры кроватей и проходов по фото не угадывались.

| Модель | Время одного выхода, примерно | Конкретные наблюдения |
|---|---:|---|
| Sunburst | 29–43 с | Лучше сохраняет исходник в этой выборке; в первой гостиной рабочее место не подтверждено, в детской №2 открывание рядом со стулом требует проверки |
| Nano Banana 2 | 12–15 с | Гостиная: добавлены отсутствующие на исходнике нагреватели; в другом выходе перемещена ТВ-зона относительно кронштейна. В обоих детских вариантах кровать стоит перед дверными створками |
| Nano Banana Pro | 18–25 с | Одна кухня потеряла холодильник. Одна гостиная изменила ТВ-зону. В детских шкаф/кровать/стеллаж размещены перед существующими дверными створками |

Невозможность подтвердить двуспальность по фото не равна доказанной односпальной кровати.
Общее «закрытое хранение» не всегда означает большой шкаф; в детском брифе шкаф для одежды
запрошен явно. Требование о рабочем месте в гостиной учитывается отдельно от сохранения проёмов.
Эти наблюдения не превращаются в сантиметровую проверку открывания или сертификат безопасности.

**Решение:** Sunburst остаётся основной моделью; Pro не получил оснований стать основной только
из-за большей цены. Дешёвую модель нельзя бесконтрольно подставлять в сложные фото-правки.
Четыре сцены не доказывают, что одна модель универсально лучшая для всех квартир.

## Автопроверка результата

Исправлен deprecated `fal-ai/any-llm/vision` → `openrouter/router/vision`, `image_urls`, temperature 0,
max_tokens 2000, общий дедлайн 120 секунд. После дедлайна оплаченный запрос не отправляется снова.
Контракт: [новый API](https://fal.ai/models/openrouter/router/vision/api),
[устаревший API](https://fal.ai/models/fal-ai/any-llm/vision/api).
24/24 одиночных проверки дали валидные ответы: 15 checked, 9 review, 0 unavailable.

Статус checked не означает соответствие исходнику. Проверка пропустила, в частности, потерю
холодильника и часть перекрытий детских дверных створок; у некоторых замечаний есть ложные
срабатывания (например, о второй тумбе, которая видна в полном кадре).

Добавлен необязательный исходный кадр в проверку: сначала исходник, затем результат, явная
инструкция сравнения. Генерация передаёт исходное фото либо выбранный концепт при правке,
а не другой AI-вариант как «истину». Оба кадра в фоновой задаче ограничиваются 1280 px;
ошибка подготовки reference не уничтожает результат и оставляет одиночную проверку.
Число запросов не увеличивается. Число визуальных токенов может увеличиться.

Шесть заранее ограниченных парных контролей выполнены отдельно: повтор №2 каждой модели
на кухне и в детской. 2 review, 4 checked. Исчезновение холодильника точно не названо;
детские перекрытия всё ещё пропущены. Поэтому парная проверка остаётся рекомендательной:
не закрывает fidelity-gate, не разрешает точную расстановку и не заменяет 2D/ручную сверку.
Нового автоматического рендера по этим результатам в QA не было.

Основания оценок: [Sunburst](https://fal.ai/models/openai/gpt-image-2.5/sunburst/edit),
[Nano Banana Pro](https://fal.ai/models/fal-ai/nano-banana-pro/edit),
[Nano Banana 2](https://fal.ai/learn/tools/how-to-use-nano-banana-2).
Денег на новые 24 рендера или автоматическое повторение не потрачено.

Приватные ignored-артефакты: `output/model-bench-funded-2026-09-27`,
`output/quality-bench/plan-74-77-reviewed-page-funded-sonnet45`, `...-funded-sonnet5`,
`...-funded-sonnet45-schema`. Источники PDF с адресным блоком в Git не добавляются.
Четыре `*--sheet.png` показывают SOURCE и 6 выходов; номера: 1 Sunburst, 2 Nano 2, 3 Pro.

CLI из `apps/web`: `bun --env-file=../../.env run scripts/interior-model-benchmark.ts MODE RUN_ID`.
`prepare` создаёт новый manifest; `render`, `review`, `paired` помечают попытку ДО сети
и не запускаются повторно для того же run-id. `sheets` локально строит листы без API.
Тестирование кодов/очереди не оплачивается. Сохраняются SHA исходника, задания и выхода;
никакие секреты в отчёт не пишутся. Старые QA-выходы не перезаписаны.

Проверка кода: 1337 веб-тестов в 110 файлах, typecheck всех 7 пакетов, lint и production build
проходят локально. Локальная сборка не доказывает обновление сайта.
