# ADR-001. Стек проекта

Статус: принято. Дата: 2026-09-06.

## Контекст

Uyut — веб-сервис с тяжёлой фоновой обработкой (генерация изображений, сегментация, подбор по векторным эмбеддингам) и сравнительно небольшим объёмом классического CRUD. Разработчик один, бюджет на инфраструктуру минимальный, аудитория российская: персональные данные должны храниться в РФ, платежи идти через российский эквайринг. Нужен стек, на котором можно быстро двигаться в одиночку и который не требует отдельных усилий на эксплуатацию.

## Решение

| Слой | Выбор | Почему |
|---|---|---|
| Пакеты и скрипты | Bun | Один инструмент для workspaces, установки, скриптов и запуска TypeScript без сборки. Заметно быстрее npm. |
| Runtime сервера | Node 24 LTS | Next.js официально поддерживается только под Node. Bun остаётся инструментом разработки, а не средой исполнения в production: так мы не ловим несовместимости в зависимостях. |
| Фреймворк | Next.js 16, React 19 | Server Components сокращают клиентский бандл, Server Actions закрывают большую часть мутаций без отдельного API. Turbopack включён по умолчанию. |
| Стили | Tailwind CSS 4 | CSS-first конфигурация, токены дизайн-системы живут в CSS-переменных. |
| Язык | TypeScript 5.9, strict | Строгий режим плюс `noUncheckedIndexedAccess`. Мажорные версии 6 и 7 появились недавно, и не все инструменты их поддерживают одинаково; вернёмся к вопросу позже. |
| ORM | Drizzle | Полностью типобезопасен, миграции читаются как SQL, нет отдельного рантайма. |
| База | PostgreSQL 17 + pgvector | Каталог, пользовательские данные и векторный поиск в одной базе. Отдельная векторная СУБД не нужна при объёме в десятки тысяч позиций. |
| Аутентификация | Better Auth | Сессии, верификация email, magic link и организации из коробки, типобезопасный API. Схема таблиц под неё заложена с первой миграции. |
| Фоновые задачи | Trigger.dev v4 (Cloud) | Durable execution, ретраи, логи и realtime без собственной очереди. Задачи деплоятся из CI, отдельный воркер на сервере не нужен. Бесплатного тарифа достаточно для старта. |
| Кэш и rate limit | Redis + serverless-redis-http | Клиенты Upstash работают по REST, а данные при этом остаются на нашем сервере. В dev и в production один и тот же интерфейс. |
| Файлы | S3-совместимое хранилище | Selectel Object Storage в production (данные в РФ), MinIO локально. |
| Ошибки | Sentry | Единый сбор ошибок для браузера и сервера. Без DSN SDK выключен, поэтому локально ничего не отправляется. |
| Качество кода | Biome, Vitest, Playwright | Biome заменяет ESLint и Prettier одним быстрым инструментом. Vitest для юнитов, Playwright для сквозных сценариев. |
| Монорепа | Bun workspaces + Turborepo | Пакеты потребляются как исходники TypeScript без шага сборки; Turborepo даёт кэш и порядок задач. |
| Деплой | Docker-образ + Coolify на VPS | Один сервер, git-push деплой, автоматический HTTPS, preview-окружения. Образ собирается из `apps/web/Dockerfile`, миграции применяются при старте контейнера. |
| CI | GitHub Actions | Линт, типы, юниты, сборка и smoke-тест на каждый push и PR. |

## Что сознательно не делаем

- Микросервисы, GraphQL, Kubernetes. Одно приложение, одна база, один воркер задач.
- Собственный хостинг моделей. Все модели через API провайдеров.
- Скрапинг магазинов. Только партнёрские фиды.

## Последствия

- Локальная разработка требует Docker для базы, Redis и MinIO. Всё поднимается одной командой.
- Переменные окружения валидируются Zod-схемой при старте сервера: неправильная конфигурация падает сразу, а не на первом запросе.
- Trigger.dev Cloud и Sentry — внешние сервисы за пределами РФ. В задачи и ошибки не должны попадать персональные данные пользователей; это правило проверяем при добавлении каждой задачи.
- Redis доступен приложению только через REST-прокси. Если понадобится нативный протокол (pub/sub, streams), придётся добавить второй клиент.
