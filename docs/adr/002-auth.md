# ADR-002. Модель аутентификации

Статус: принято. Дата: 2026-09-06.

## Контекст

Нужны регистрация по почте и паролю, подтверждение почты, сброс пароля, защита от перебора и аудит действий. Всё это должно работать в одном Next.js-приложении без отдельного auth-сервиса и без раскрытия, какие адреса зарегистрированы.

## Решение

**Сессии, а не JWT.** Better Auth хранит сессии в таблице `sessions`, в браузер уходит только непрозрачный токен в cookie `HttpOnly`, `Secure` в production, `SameSite=Lax`. Срок сессии 30 дней с продлением раз в сутки. Кэш сессии в cookie на 15 минут снимает обращение к базе на каждом запросе; та же роль у Redis как вторичного хранилища. Пара «access-токен на 15 минут плюс refresh на 30 дней» из первоначального плана не реализована: серверная сессия даёт то же поведение и при этом отзывается мгновенно, например при смене пароля.

**argon2id** для паролей: 64 MiB памяти, 3 прохода, 4 потока. Библиотечный scrypt заменён на нативный `@node-rs/argon2`.

**Подтверждение почты не блокирует вход.** После регистрации пользователь сразу в сессии и видит плашку «почта не подтверждена»; без подтверждения нельзя будет оплатить проект. Ссылка из письма живёт сутки.

**Сброс пароля**: ссылка живёт 30 минут, одноразовая, после смены все остальные сессии отзываются. Ответ на запрос сброса одинаков для любого адреса, а письмо отправляется без ожидания, чтобы время ответа не выдавало существование аккаунта.

**Лимиты.** Вход: 5 попыток в минуту с одного IP плюс 10 в час на один адрес независимо от IP. Регистрация: 3 в час с IP. Запрос сброса и повторная отправка письма: 5 в час с IP. Общий потолок на любой запрос: 300 в минуту с IP, проверяется в прокси Next.js до рендера. Счётчики живут в Redis, поэтому лимиты общие для всех инстансов.

**IP клиента** берётся из `X-Forwarded-For`. За обратным прокси Coolify это правильный адрес; без прокси заголовок можно подделать, что для лимитов означает лишь возможность обойти их, а не получить чужой доступ. При выходе в production нужно ограничить доверие заголовку списком адресов прокси, это отмечено в чек-листе фазы полировки.

**Аудит.** Регистрация, вход, выход, запрос и завершение сброса пароля, смена пароля, подтверждение почты и изменения профиля пишутся в `audit_log` с IP и user agent. Ошибка записи аудита не ломает пользовательский запрос.

**CSRF.** Эндпоинты Better Auth принимают запросы только с доверенных origin, Server Actions защищены проверкой origin самим Next.js. Дополнительный double-submit-токен не вводился: у мутаций Фазы 1 нет побочных эффектов, ради которых он нужен.

## Последствия

- В базе появились таблицы `sessions`, `accounts`, `verifications`, `audit_log`; для пользователей используется существующая `users` с полями `display_name` и `avatar_url`, сопоставленными полям `name` и `image` библиотеки.
- Локально письма ловит Mailpit из docker-compose, веб-интерфейс на порту 8025. Реальный транспорт подключается заменой адаптера `EmailSender`, интерфейс приложения не меняется.
- Тесты Playwright читают письма через REST-интерфейс Mailpit и приходят с уникальных адресов `X-Forwarded-For`, чтобы лимиты одного сценария не мешали другим.
