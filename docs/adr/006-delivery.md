# ADR-006. Список покупок, смета, PDF и оплата

Статус: принято. Дата: 2026-09-07.

## Контекст

После подбора товаров человеку нужно забрать результат: собрать покупки в один список, понять, сколько всё стоит вместе с работами, и получить документ, который можно показать бригаде и семье. Спека описывает shopping list, автосмету, PDF в редакторском стиле с ТЗ мастеру от Claude, разовую покупку проекта за 1 500 ₽ и подписку Pro за 999 ₽ в месяц через ЮKassa.

## Решение

**Список покупок — один на проект.** Строка знает комнату и предмет рендера, с которого пришёл товар: так список группируется по комнатам, а главный концепт комнаты в PDF выбирается по тому, откуда добавляли покупки. Повторное нажатие «В список» на том же предмете увеличивает количество, а не дублирует строку. Перекрашенный предмет уносит свотч как вариант цвета.

**Смета — чистая функция в пакете каталога.** Мебель считается по строкам списка с ценой варианта, работы — по площади комнат: черновая отделка даёт черновые и чистовые ставки, готовая отделка — ничего, кроме случая, когда заказчик включил «обновить отделку». Ставки живут в окружении (`WORKS_ROUGH_RUB_PER_M2`, `WORKS_FINISH_RUB_PER_M2`) и везде подписаны как ориентир: «примерная стоимость работ, уточняйте у мастеров». Одна функция обслуживает страницу итогов, страницу проекта и PDF, поэтому цифры совпадают.

**PDF собирается TypeScript-шаблоном, а не Handlebars.** Данные документа строго типизированы, форматтеры цен и площадей общие с продуктом. Шрифты Literata, Onest и JetBrains Mono вшиты из пакетов fontsource как base64: Fraunces из ТЗ фазы не содержит кириллицы, а Literata уже стоит в интерфейсе. Печатает Chromium через Playwright внутри задачи Trigger.dev; водяной знак бесплатной версии — фиксированный слой, который Chromium повторяет на каждой странице печати, лента с предложением оплаты — обычный блок в начале каждого раздела, потому что фиксированные элементы с отступом в печати ведут себя непредсказуемо. Обложка печатается без полей через `@page :first`.

**ТЗ мастеру пишет Sonnet 4.5 через fal, по комнате параллельно.** Одним запросом две комнаты занимали 45 секунд, по одной — вдвое меньше. Модель отвечает строгим JSON с шестью фиксированными разделами, вёрстка наша. Результат кэшируется по хэшу входных данных в истории экспортов: повторная сборка без изменений не ходит в модель и занимает пару секунд. Бесплатный предпросмотр без ТЗ допустим, оплаченный документ без ТЗ не отдаётся.

**Платежи — через порт провайдера.** Интерфейс `PaymentProvider` реализуют ЮKassa и фейковый провайдер, который отвечает успехом сразу и без редиректа; без ключей магазина работает фейк, на нём живут разработка и CI. Единственное место, где оплата становится фактом, — `applyPayment`: она перечитывает платёж из API провайдера, сверяет сумму и переводит покупку из pending в paid одним update с условием по статусу. Её вызывают и webhook, и страница возврата, и фейковый провайдер, поэтому повторные уведомления и гонки ничего не удваивают. У ЮKassa нет подписи уведомлений: адрес отправителя сверяется со списком подсетей, в бою чужой адрес отклоняется, а телу уведомления не доверяют вовсе — из него берётся только id платежа.

**Подписка Pro пока без автосписаний.** Первая оплата включает месяц, ежедневная задача за три дня до конца шлёт письмо с кнопкой продления, после конца периода переводит подписку в past_due. Способ оплаты при этом сохраняется на будущее: когда ЮKassa включит автоплатежи для магазина, списание по нему не потребует миграции.

**Free-план ограничен на уровне действий.** Второй проект без Pro не создаётся ни из онбординга, ни со страницы проектов; на странице проектов вместо «Новый проект» предлагается Pro. Оплаченный проект и любой проект владельца с Pro получают PDF без водяного знака.

**Письмо после оплаты уходит из задачи экспорта.** Ссылка на PDF подписывается на срок из `PDF_URL_TTL_HOURS`, рядом ссылка на страницу итогов, где файл доступен всегда. Транспорт тот же SMTP, что у писем регистрации.

## Последствия

- Себестоимость экспорта: около пяти центов на ТЗ при первой сборке, ноль при повторе; печать в очереди укладывается в бесплатный тариф. Первая сборка занимала 37–40 секунд, повторная — 2–5.
- Тестовый контур ЮKassa требует статуса самозанятого или ИП; до появления ключей всё проверяется на фейковом провайдере, переключение — две переменные окружения.
- Уведомления ЮKassa до локальной машины не доходят без туннеля, поэтому статус платежа всегда перепроверяется при возврате на сайт.
- Автосписания, чеки 54-ФЗ и СБП появятся вместе с боевым магазином.
